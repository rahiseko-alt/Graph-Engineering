## 気づいたこと

- **仕組みの検査が2回、実際に働いた。** 1回目は検収条件の減少（6行→4行）を捕まえ、本物の抜けを見つけさせた。2回目は仕様が2件になった時点で「どれを検査するか明示しろ」と止めた。どちらも黙って緑にはならなかった
- **トークン消費を単位ごとに取る手段が無い。** これは事前に Rabbit Hole として挙げていたとおりだった。比較の指標としては、所要時間・再実行回数・人の介入回数のほうが実際に取れる
- 作業領域の分離に必要だったのは git だけだった。新しい実行基盤を1行も書いていない
- 独立した単位を作るには**設計側の判断が要る**。`parse-date` と `holidays` を別ファイルに分ける判断を計画時に入れなければ、並列にできる単位が生まれなかった
