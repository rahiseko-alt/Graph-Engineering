## 比較に使う対象 (T002)

- **対象名**: `business-days`
- **依頼文**: 「開始日と終了日を渡すと、その間の営業日数を返すコマンドがほしい。土日と、指定した休業日は数えない。」
- **置き場所**: このリポジトリの `sandbox/business-days/`

### なぜこの対象を選んだか

| 条件 | 満たしているか |
|---|---|
| 工程そのものではない成果物である | **満たす。** 営業日を数えるコマンドであり、この工程とは無関係 |
| 分解が10単位以内に収まる | 満たす見込み（日付の検査 / 休業日の読み込み / 数える処理 / コマンドの入口 / テスト） |
| 独立した作業が2つ以上ある | 満たす見込み（日付の検査と休業日の読み込みは互いに独立） |
| 機械だけで動作を確かめられる | **満たす。** 画面を持たず、終了コードと標準出力で判定できる |
| 停止4領域に触れる | **満たす。** 「日付」に該当し、想定外の日付でその場で停止する挙動を検査できる |

### 当初の条件からの変更点

`specs/001-graph-engineering-pipeline/tasks.md` の T002 は当初「このリポジトリ**外**の成果物」を条件にしていました。実際には、別リポジトリへの書き込みがこのセッションの権限範囲外であるため、**同じリポジトリの `sandbox/` 配下**に置きます。

この変更で失われる性質はありません。T002 の条件の狙いは「工程で工程を作ると、詰まった原因が工程側か対象側か切り分けられなくなる」ことの回避であり、`sandbox/business-days/` は工程とは独立した成果物なので、その狙いは保たれます。

### 依頼者への確認回数について

整合検査 (`/speckit-analyze`) の指摘 D1 は「検証用の案件でも門①の二択が発生し、依頼者から見た応答が通算2回になる」でした。

**実際には1回のままです。** この対象は測定のために工程側が選んだものであり、依頼者から受けた依頼ではありません。したがって `business-days` の門①における「依頼者」は工程側であり、依頼者へ二択を出しません。依頼者が応答したのは `001` の門①の1回だけです。

# 比較: business-days (2026-08-28)

同じ依頼を2通りで実行した結果です。**この結果は、この仕組みにとって都合の良いものではありません。そのまま記録します。**

| 指標 | single（単一AIに1回で） | graph（分けて隔離して） | どちらが良いか |
|---|---|---|---|
| トークン消費 | **46,767** | **取得できず**（案件001の設計・調査・門①・前提の確認と混ざり、分離できない） | 比較不能 |
| 所要時間 | **1.5分** | 実装だけで約3分。仕様・計画・分解・着手判定を含めるとさらに長い | **single** |
| 一発成功 | **是** | 否（ただし失敗は測定のために意図的に作ったもの） | 比較に使えない |
| 検査通過 | **是**（5/5） | **是**（5/5） | 同じ |
| 再実行回数 | 0 | 1（意図的な失敗の修正） | 比較に使えない |
| 人の介入回数 | **0** | **0** | 同じ |
| 既存の破壊 | 0 | 0 | 同じ |
| コンテキスト量 | 依頼文1文 | 単位あたり1〜2ファイル | graph の方が小さい |
| 作ったファイル数 | 6 | 9 | — |
| 単体テスト件数 | 11 | 25 | graph の方が多い |

## この1件から言えること

**この規模の依頼では、構造化した実行が単一AIより良い結果を出していません。** 受入検査5件はどちらも一発で通り、検収条件の外側（読めない休業日行、年の範囲外）を当てても、どちらも黙って数値を返さずに止まりました。到達点は同じでした。

一方、構造化した側は、仕様・計画・調査・分解・着手判定・記録という工程を通っており、**明らかに多くの時間とトークンを使っています。**

## この1件から言えないこと

- **規模が大きい場合にどうなるか。** この対象は5ファイル・1コマンドで、単一AIの一度の作業に収まる大きさでした。レポートが構造化の利点として挙げた「成功した仕事を残して失敗した箇所だけ修復する」は、**そもそも作り直す量が小さい対象では利点になりません**
- **どこから構造化が引き合うか。** 測定は1件だけです。境目を示す根拠はありません
- **トークンの実際の差。** graph 側を分離して取る手段が無いため、最も知りたかった比較ができていません

## それでも残った差

数値に出ないところで、次の差がありました。

- **検査が2回、実際に働いた。** 検収条件が6行から4行へ減ったことを機械が捕まえ、本物の抜け（中断しても進捗が失われないこと／各作業の状態が読めること）を見つけさせました。もう1回は、仕様が2件になった時点で「どれを検査するか明示しろ」と止めました。single 側にはこの働きがありません
- **single 側は「決めた」ことを自己申告しています。** 期間が両端を含むか、休業日ファイルの書式を、依頼文に無いまま自分で決めて報告してきました。今回はその判断が正しかったのですが、**正しかったことを確かめる手段は、こちらが後から検査を当てるまで存在しませんでした**

## 次に測るべきこと

境目を知るには、**単一AIの一度の作業に収まらない大きさの対象**で同じ測定をする必要があります。この1件はその条件を満たしていません。
