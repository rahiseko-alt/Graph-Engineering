- **対象**: `specs/001-graph-engineering-pipeline/spec.md` の Critical Assumptions

## 何を確かめたか

**CA-002**: 失敗した単位だけの再実行が、実際の失敗で機能するか
**CA-004**: 分離した作業領域の統合で、変更の取りこぼしや衝突が起きないか

## 手順と実測値

基点: `914561a`

| 順 | 操作 | 結果 |
|---|---|---|
| 1 | 同じ基点から作業領域を2つ作る（`unit-a` / `unit-b`） | 2つとも基点 `914561a` に作成 |
| 2 | 単位A に正しい変更、単位B に検査へ引っ掛かる変更を入れる | それぞれ1コミット |

## 赤 / 緑 / 戻して赤

- **赤**: 手順4。単位B が `ERROR: 1` で落ちる
- **緑**: 手順6。原因を取り除くと `RESULT: PASS`
- **戻して赤**: 同じ変更（行内免除を1件足す）を戻すと、手順4と同一のエラーで再び落ちる

## 判定

| 前提 | 判定 | 根拠 |
|---|---|---|
| CA-002 | **成立** | 赤い単位を直す間、緑の単位のコミットが1件のまま変化しなかった（作り直し0件） |

**新しい実行基盤を1行も書いていません。** 使ったのは git の作業領域分離と、既存の検査スクリプト2本だけです。spec.md の Appetite（既存の公式部品の組み合わせで成立する範囲まで）が、この範囲では成立しています。
