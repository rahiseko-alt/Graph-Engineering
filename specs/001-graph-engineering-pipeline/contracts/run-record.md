# Contract: 実行1回分の記録 (Run Record)

**Date**: 2026-08-28

この形式が、この案件で新しく定義する**唯一の**取り決めです。指標そのものは添付レポート第29節の一覧をそのまま使い、追加も削除もしません。

## 置き場所

`docs/measurements/YYYYMMDD-<対象名>-<実行方式>.md`

- `<実行方式>` は `single`（単一AIに全部やらせた場合）または `graph`（この構造で走らせた場合）のいずれか
- SC-003 は、同じ `<対象名>` について `single` と `graph` の2件が揃うことを求めます

## 形式

```markdown
# 実行記録: <対象名> / <single | graph>

- **日付**: YYYY-MM-DD
- **対象**: 何を作らせたか（1文）
- **実行方式**: single | graph
- **使った機構**: （graph の場合のみ。例: /speckit-tasks + /batch）

## 指標

| 指標 | 値 | 取得方法 |
|---|---|---|
| トークン消費 | | |
| 所要時間（分） | | |
| 一発成功 | 是 / 否 | |
| 検査通過 | 是 / 否 | |
| 再実行回数 | | |
| 人の介入回数 | | |
| 既存の破壊（件） | | |
| コンテキスト量 | | |

## 検査の出力

（`check-test-integrity.sh` / `check-catastrophic.sh` / E2E の実際の出力を貼る）

## 気づいたこと

（数値に表れないもの。1行1件）
```

## 規則

1. **値を空欄のまま「完了」としない。** 取得できなかった項目には「取得できず」と、その理由を書く。
2. **推定値には「推定」と明記する。** 実測と混ぜない（`AGENTS.md` LEVEL A-7）。
3. **指標を増やさない。** 増やしたくなった時点で、それは新しい指標の考案であり No Gos に当たる。
4. **過去の記録を書き換えない。** 追記のみ。
