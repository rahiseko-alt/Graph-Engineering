# Feature Specification: 営業日を数えるコマンド

**Feature Branch**: `002-business-days`

**Created**: 2026-08-28

**Status**: 確定（門① 2026-08-28 通過。判定者は工程側）

**Input**: User description: "開始日と終了日を渡すと、その間の営業日数を返すコマンドがほしい。土日と、指定した休業日は数えない。"

> **この案件の依頼者は工程側です。** `specs/001-graph-engineering-pipeline/` の測定のために選んだ対象であり、外部の依頼者から受けた依頼ではありません。したがって門①の二択は工程側が判定します（`docs/measurements/README.md`）。

## Problem *(mandatory)*

期間内に何日働けるかを知りたいときに、カレンダーを見ながら土日と休業日を手で除いて数えています。数え間違いが起き、期間が長いほど時間が掛かります。

### Desired Outcome

期間を渡すだけで、その間に働ける日数が正しく分かること。

### Opportunities

- 手で数えるため、日数が増えるほど間違いが増える
- 休業日の一覧が人によって違い、同じ期間でも答えが食い違う
- 数え直しのたびに同じ作業が発生する

## Appetite *(mandatory)*

**1日。** 収まらない場合は期間を延ばさず、扱う範囲を削ります。

## Solution *(mandatory)*

開始日と終了日を受け取り、土日と、指定された休業日を除いた日数を返すコマンドを作ります。休業日は日付の一覧を書いたファイルで渡します。

## Rabbit Holes

- 開始日が終了日より後の場合の扱い
- 存在しない日付（2月30日など）や、年の範囲外の値の扱い
- 休業日ファイルが無い場合、壊れている場合の扱い

## No Gos *(mandatory)*

- 祝日の自動判定（国・地域ごとの祝日データの取り込み）
- 時刻・タイムゾーンの考慮（日付単位のみ扱う）
- 画面・Web API の提供
- 営業時間や半休の概念

## 2. User Scenarios & Testing — 検収条件 *(mandatory)*

### User Story 1 - 期間を渡すと営業日数が返る (Priority: P1)

**Why this priority**: これが動かなければ何も価値がありません。

**Independent Test**: コマンドを1回実行し、標準出力の数値を確認するだけで検証できます。

**Acceptance Scenarios**:

1. **Given** 休業日を1件も指定していない。**When** 開始日 `2026-09-01`（火）と終了日 `2026-09-07`（月）を渡して実行する。**Then** 標準出力に `5` が出力され、終了コードが `0` になる。
2. **Given** 休業日として `2026-09-03` を1件指定している。**When** 同じ期間を渡して実行する。**Then** 標準出力に `4` が出力され、終了コードが `0` になる。
3. **Given** 開始日と終了日が同じ土曜日 `2026-09-05` である。**When** 実行する。**Then** 標準出力に `0` が出力され、終了コードが `0` になる。

---

### User Story 2 - おかしな日付はその場で止まる (Priority: P1)

**Why this priority**: 日付は停止4領域です。想定外の値をそのまま数えて返すと、誤った日数を正しい答えとして扱ってしまいます。

**Independent Test**: 不正な日付を渡して終了コードを見るだけで検証できます。

**Acceptance Scenarios**:

1. **Given** 存在しない日付 `2026-02-30` を開始日に渡す。**When** 実行する。**Then** 数値を出力せず、標準エラーに理由が出て、終了コードが `1` になる。
2. **Given** 開始日 `2026-09-10` が終了日 `2026-09-01` より後である。**When** 実行する。**Then** 数値を出力せず、標準エラーに理由が出て、終了コードが `1` になる。

---

### Edge Cases

- 休業日ファイルに、期間の外の日付や重複した日付が含まれていても結果が変わらないこと
- 休業日ファイルに読めない行が含まれていた場合に、黙って無視せず停止すること

## Requirements *(mandatory)*

- **FR-001**: 開始日と終了日を受け取り、両端を含む期間の営業日数を標準出力に出す
- **FR-002**: 土曜日と日曜日を営業日から除く
- **FR-003**: 指定された休業日を営業日から除く
- **FR-004**: 存在しない日付、書式が違う日付、開始日が終了日より後の場合は、数値を出力せず終了コード `1` で停止する
- **FR-005**: 休業日ファイルに読めない行がある場合は、黙って無視せず終了コード `1` で停止する

### Key Entities

- **期間**: 開始日と終了日（両端を含む）
- **休業日**: 営業日から除く日付の一覧

## 4. 停止4領域 (Fail Fast) *(mandatory)*

- **金額**: なし
- **日付**: **該当する。** 開始日・終了日・休業日ファイルの各行。書式違い、存在しない日付、年の範囲外、開始日が終了日より後、のいずれかを受け取った時点で停止する
- **権限**: なし（コマンドであり、認証を持たない）
- **データの削除・上書き**: なし（読み取りのみ。ファイルを書き換えない）

### 保護対象ルート一覧

- NONE

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 期間と休業日を渡して実行したとき、手で数えた結果と **100%** 一致する
- **SC-002**: 想定外の日付を渡したとき、数値を出力する経路が **0件** である（必ず終了コード `1` で止まる）
- **SC-003**: 1回の実行が **1秒以内** に終わる（1年以内の期間の場合）

## Assumptions *(mandatory)*

### Critical Assumptions (Assumption Tests)

| # | Assumption | 偽だったら何が変わるか | Evidence | 状態 |
|---|---|---|---|---|
| CA-001 | 営業日の定義は「土日と指定休業日を除いた日」でよく、祝日の自動判定は要らない | Solution の変更。祝日データの取り込みが必要になり、Appetite を超える | 依頼文が「土日と、指定した休業日は数えない」と明示しており、それ以外の除外条件を挙げていない | 確認済 |

### Non-critical Assumptions

- 日付の書式は `YYYY-MM-DD` でよい
- 休業日ファイルは1行1日付の平文でよい
- 出力は数値1行だけでよい
